# دليل النشر — كيف يعمل برنامج APL على خادم

**الإجابة المختصرة: نعم، أي خادم Python عادي يكفي.** لا يوجد وقت تشغيل خاص ولا حاوية إلزامية ولا خدمة سحابية معينة.

## لماذا يعمل ذلك

APL ليست مفسراً مستقلاً: المترجم يحوّل ملف `.apl` إلى كود Python عادي، ثم يشغّله CPython. لذلك برنامجك يرث كل ما يعرفه Python عن النشر: أي VPS، أي Docker، أي منصة فيها Python 3.14 أو أحدث تكفي.

## الاعتماديات

- **النواة**: لا تحتاج شيئاً سوى Python 3.14+.
- **برنامجك**: يحتاج فقط حزم Python للمكتبات التي يستعملها فعلاً. تطبيق Flask مثلاً يحتاج `pip install flask`، وبوت تيليجرام يحتاج `pip install python-telegram-bot`، وهكذا.

## الطريقة 1: التشغيل المباشر على الخادم

```bash
git clone https://github.com/AmmarBasha2011/APL.git
cd APL
python -m venv .venv && . .venv/bin/activate
pip install .          # يوفر الأمر apl
pip install flask      # فقط ما يستعمله برنامجك
python apl.py /مسار/إلى/app.apl
```

## الطريقة 2: ترجمة مسبقة ثم Python خالص

يمكنك تحويل برنامجك إلى ملف Python واحد مكتفٍ ذاتياً (يتضمن أدوات وقت التشغيل) وشحنه وحده:

```bash
apl transpile app.apl > app.py
python app.py
```

هذه الطريقة مجربة: الملف الناتج يعمل بـ `python` مباشرة بدون مستودع APL بجانبه، ويحتاج فقط حزم Python التي يستعملها البرنامج.

## مثال مختبَر: تطبيق ويب Flask

الملف `app.apl`:

```apl
المتغير app = تطبيق_فلاسك(__name__)

مسار_فلاسك("/")
دالة الرئيسية():
    ارجع "مرحبا من APL"

مسار_فلاسك("/health")
دالة صحة():
    ارجع استجابة_جسون({"حالة": "سليم"})

لو __name__ == "__main__":
    شغل(host="127.0.0.1", port=5056)
```

تم نشره فعلياً بالطريقتين ونجح:

```bash
# تطوير: خادم Flask المدمج
python app.py            # curl http://127.0.0.1:5056/  ->  مرحبا من APL

# إنتاج: خادم WSGI حقيقي (gunicorn) بنفس الملف بدون أي تعديل
pip install gunicorn
gunicorn -w 2 -b 0.0.0.0:8000 app:app
# curl http://127.0.0.1:8000/health  ->  {"حالة": "سليم"}
```

ملاحظتان مهمتان من التجربة:

- **`لو __name__ == "__main__":` قبل `شغل(...)`** تجعل نفس الملف يعمل تطويراً (خادم مدمج) وإنتاجاً (gunicorn يستورد `app` بدون تشغيل الخادم المدمج). لا تحذفها.
- **اكتب مسارات الروابط بأحرف لاتينية** (`"/health"`)؛ المسار العربي قد لا يصل كما كتبته عبر بعض العملاء والوسطاء.
- `شغل(...)` خادم تطوير، لا تستخدمه وحده في الإنتاج — استخدم gunicorn أو uvicorn أمامه.

## بوتات تيليجرام والعمليات الطويلة

نفس المبدأ: البوت برنامج Python طويل العمر. شغّله بأي مدير عمليات (systemd، Docker، supervisor). مكتبة تيليجرام العربية موثقة في [telegram-library.md](telegram-library.md)، وتحتاج توكن البوت و`pip install python-telegram-bot`. (تُرجمت أمثلة البوت وتحققنا من صياغتها، لكن لم نختبر اتصالاً فعلياً بالتيليجرام لعدم وجود توكن.)

## Docker (قالب بداية — لم يُختبر بناؤه هنا)

```dockerfile
FROM python:3.14-slim
WORKDIR /app
COPY . .
RUN pip install --no-cache-dir . flask
CMD ["python", "apl.py", "app.apl"]
```

## خلاصة القرار

| سؤال | جواب |
|------|------|
| هل يعمل على سيرفر Python عادي؟ | نعم، مباشرة |
| هل أحتاج خادم APL خاص؟ | لا يوجد أصلاً |
| كيف أنشر للإنتاج؟ | transpile ثم gunicorn/uvicorn أمام تطبيق الويب |
| الاعتماديات؟ | Python 3.14+ وحزم المكتبات المستعملة فقط |
